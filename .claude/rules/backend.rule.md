## 2. 목적 & 사용 모델

zipboda-api 백엔드 코드를 작성·수정할 때 따르는 규칙이다. FE의 `frontend.rule.md`와 동일하게 두 부분으로 나뉜다.

- **Core (§3~§5)** — 스택 무관 원칙. 이식 시 수정하지 않는다.
- **Project Profile (§6)** — 프로젝트별 가변값을 채우는 편집 구역. 값이 필요한 Core 규칙은 슬롯 ID(`BP1`~`BP15`)를 참조한다.

적용 범위: `src/**/*.ts` 서버 코드. 프론트엔드 규칙(FSD·디자인 토큰 등)은 적용하지 않는다.

## 3. 절대 규칙 (A1~A4)

위반 시 즉시 멈춰 사용자에게 보고한다.

| # | 규칙 |
|---|------|
| **A1** | 실 연동 시 Mock·하드코딩·시드 폴백을 **같은 PR에서** 전량 제거. "나중에 정리" 금지 |
| **A2** | API 계약(URI·Method·권한·Req/Res)은 **API 및 인터페이스 정의서**(BP15)를 단일 기준으로 따른다. 계약 변경은 정의서 먼저 갱신 후 구현 |
| **A3** | API 갭(엔드포인트·필드 누락)은 임의 구현 대신 정의서에 등록(BP15). 미연계 외부데이터는 임의 값 대신 공백 |
| **A4** | 시크릿(DB·PG·토큰·키)을 코드/리포지토리에 하드코딩 금지. `.env`·시크릿 매니저만 사용 |

## 4. 핵심 컨벤션 (B1~B18)

| 그룹 | # | 규칙 | 참조 |
|------|---|------|------|
| 구조·계층 | B1 | 계층 단방향 `Controller → Service → Repository`. Controller=입출력/검증, Service=비즈니스/트랜잭션, Repository=DB 접근 | backend-architecture |
| | B2 | 도메인은 모듈로 분리, 모듈 간 의존은 명시적 import·순환 금지(DAG) | backend-architecture |
| | B3 | 내부 모듈은 alias 사용, 깊은 상대경로(`../../../`) 금지 | BP4 |
| 계약·응답 | B4 | **모든 응답은 엔벌로프** `{ success, data, error }` (BP5) | BP5 |
| | B5 | 코드성 값은 공통 인터페이스(ITF-*), 오류는 오류코드(ERR-*)를 사용. 임의 문자열 코드 금지 | BP6 |
| | B6 | 같은 종류 유스케이스는 일관된 반환 형태 유지(부분적으로 raw/엔벌로프 혼용 금지) | — |

| | B9 | DB 타입은 ORM 생성 타입 활용, 외부 노출 타입은 mapper로 변환(내부 엔티티 직접 노출 금지) | code-organization |

| | B11 | 예상 오류(검증/권한/미존재/충돌)와 500을 구분. 스택 트레이스는 서버 로그에만 | — |
| | B12 | 부분 실패·빈 결과·null을 명시적으로 분기 | — |
| 보안·데이터 | B13 | 인증(BP3)·인가(RBAC)는 **서버에서 강제**, 민감 액션 재인증 | BP3 |
| | B14 | 개인정보(무주택·소득·연락처 등)는 저장 암호화·조회 마스킹·최소 접근·**감사 로그** | BP12 |
| | B15 | 쓰기 정합이 필요한 작업은 트랜잭션 + 적절한 잠금. 결제/재시도는 멱등키 | — |

## 6. Backend Project Profile (Zipboda 확정값)

| ID | 슬롯 | 값 |
|----|------|-----|
| BP1 | 런타임/프레임워크 | **NestJS (Node.js + TypeScript)** |
| BP2 | DB / ORM / 마이그레이션 | **PostgreSQL + Prisma** (Prisma Migrate, ERD 동기화) |
| BP3 | 인증/인가 | **JWT(access/refresh) + RBAC**(ITF-012: 비회원/시민/운영자/관리자), 서버 강제 |
| BP4 | 경로 별칭 | `@/*`, 공유 계약 타입 `@zipboda/shared` |
| BP5 | 응답 표준 | 엔벌로프 `{ success: boolean, data: T|null, error: {code,message}|null }` |
| BP6 | 코드/오류 체계 | 인터페이스 `ITF-001~013`, 오류코드 `ERR-001~016` (API 정의서) |
| BP7 | 파일/자산 | 오브젝트 스토리지(S3 호환) + CDN + 서명 URL (3D glTF/GLB 등) |
| BP8 | 결제(2차) | 국내 PG(멱등키·웹훅), 재고 동시성 잠금 |
| BP9 | 외부 연계 | 공공데이터 **LH/SH/GH/IH** — 기관별 어댑터→정규화→upsert, 실패 격리·재처리 |
| BP10 | 캐시/성능 | 목록 P95 ≤ 500ms, 필요 시 캐시·인덱스, N+1 방지 |
| BP11 | 배치/스케줄 | 공공데이터 동기화 배치 + 수동 실행(API-114) |
| BP12 | 로깅·감사·모니터링 | 구조적 로깅·메트릭·트레이싱, 관리자 변경/삭제 **감사 로그 append-only**(API-192) |
| BP13 | 테스트 | 단위 Jest · 통합 Supertest · 부하 k6 (test-guide.rule.md), 핵심 커버리지 ≥ 80% |
| BP14 | 시크릿 관리 | `.env`(gitignore) / 시크릿 매니저. 하드코딩 금지 |
| BP15 | API 계약·갭 문서 | `../zipboda-web/docs/ZIPBODA_API 및 인터페이스 정의서_v0.1.xlsx` (zipboda-web 대표 관리) |
