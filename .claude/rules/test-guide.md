## 2. 기본 원칙

- **구현 후 테스트 필수**: 기능/버그 수정 후 의도대로 동작하는지 검증한다.
- **테스트 우선 지향**: 구현과 동시 또는 직후 단위 테스트 작성.
- **실패 케이스 포함**: 성공 시나리오뿐 아니라 예외(빈 값·null·경계·네트워크 실패)를 설계에 포함.

---

## 3. 스택별 테스트 도구

| 저장소 | 단위/컴포넌트 | 통합 | E2E |
|--------|---------------|------|-----|
| **web** (Next.js) | **Vitest + React Testing Library** | MSW(API 목) | **Playwright** |
| **app** (RN/Expo) | **Jest + React Native Testing Library** | MSW | **Detox** 또는 Maestro |
| **admin** (Vite) | **Vitest + React Testing Library** | MSW | Playwright(핵심 플로우) |
| **api** (NestJS) | **Jest** | **Jest + Supertest**(엔드포인트) | 계약/시나리오 테스트, 부하: k6 |

공통: 타입체크(`tsc --noEmit`), 린트(ESLint + Prettier)는 CI 필수.

---

## 4. 체크리스트

### 4.1 정적 분석
- [ ] 구문 오류·미정의 참조 없음
- [ ] 린트/타입체크 통과

### 4.2 단위 테스트
- **독립성**: 외부 의존성은 목/스텁으로 격리(FE=MSW, api=레포지토리 목).
- **커버리지**: 핵심 비즈니스 로직 ≥ 80%.
- **명명**: `test_[대상]_[조건]_[기대결과]` 권장.

### 4.3 엣지 케이스
- [ ] null/undefined/빈 문자열/0/빈 배열 처리
- [ ] 인덱스 경계
- [ ] 네트워크 지연·API 실패 시 에러 핸들링(빈 상태/스켈레톤/재시도)
- [ ] 3D 미지원·저사양 폴백(web/app), 오프라인(app)

---

## 5. 도메인별 필수 검증(요약)

- **인증/권한**: 인가 우회 0건(서버 강제), 토큰 만료/재발급.
- **청약 신청·가점**: 트랜잭션 정합, 가점 계산 정확성 단위테스트.
- **평면도 3D**: 30fps 이상, 시점 전환/폴백.
- **커머스(2차)**: 재고 동시성·결제 멱등(초과판매·중복결제 0건).

---

## 6. 응답 전략(구현 요청 시)
1. 코드 구현 → 2. 테스트 계획 요약 → 3. 테스트 코드 작성 → 4. 실행 결과(PASS) 또는 논리적 결함 없음 증명.

## 7. 회귀
- 신규 기능 추가 시 기존 테스트가 깨지지 않는지 확인. 기존 기능 수정 시 영향 모듈 테스트도 갱신.
- 테스트를 통과하지 못한 코드는 '완성'으로 간주하지 않는다.
