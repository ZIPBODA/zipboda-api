## 2. 개요

### 2.1 목적
집보다 **백엔드 API(`zipboda-api`)** 개발 계획. API 및 인터페이스 정의서(zipboda-web 대표 관리)를 1차 근거로, 요구사항ID·연관화면ID·API ID·인터페이스ID·오류코드ID를 추적한다.

### 2.2 서비스 개요
LH·SH·GH·IH 공공 청약 정보 통합, 평면도·**WebGL 3D(1·3인칭 집구경)**, 가점·구독/알림·영감·쇼룸·커뮤니티·마이, 2차 커머스. API는 web/app/admin 3개 클라이언트에 공통 계약 제공.

### 2.3 범위 / 저장소 매핑
전체 API(**API-001~199, 총 94건**)·인터페이스(ITF-001~013)·오류코드(ERR-001~016)·데이터 모델·외부 연계.
| 저장소 | 역할 | 비고 |
|--------|------|------|
| **zipboda-api** | 백엔드 API | **본 문서 대상** |
| zipboda-web/app | 사용자 클라이언트 | API 소비 |
| zipboda-admin | 운영 콘솔 | 관리자 API(100~199) 소비 |

## 3. 기술 스택 및 표준 (권장, 착수 승인 필요)

> 검토 결함 C2·api-Minor(DB/ERD) 반영.

| 항목 | 결정(권장) | 근거 |
|------|-----------|------|
| 런타임/프레임워크 | **NestJS(Node.js + TypeScript)** | 모듈/DI 구조, 규모 확장 |
| DB / ORM | **PostgreSQL + Prisma** | 관계형 정합성, 마이그레이션·타입 생성 |
| 인증/인가 | **JWT(access/refresh) + RBAC(ITF-012)** | REQ-CO-008, REQ-NF-005 |
| 파일/자산 | **오브젝트 스토리지(S3 호환) + CDN + 서명 URL** | 3D/이미지 서빙(REQ-CO-005) |
| 결제(2차) | **국내 PG(예: 토스페이먼츠) 연동, 멱등키·웹훅** | REQ-US-011 |
| 응답/오류 | 엔벌로프 `{success,data,error}` + ERR-001~016 | API 정의서 |
| 관측성 | 구조적 로깅·메트릭·트레이싱·알림 | REQ-NF-013 |

### 3.1 데이터 설계(신규 산출물)
S0~S1에 **ERD 및 스키마 정의서**를 산출한다(회원·역할·청약공고·평형·신청·가점·평면도·3D자산·영감·쇼룸·예약·커뮤니티·알림·구독·(2차)상품/장바구니/주문·**감사로그**). Prisma 스키마↔ERD 동기화.

### 3.2 공공데이터 연계(LH/SH/GH/IH)
공급기관 코드(ITF-001)별 **원천 오픈API 규격 조사→어댑터별 수집→정규화 매핑→적재(upsert)→동기화 이력**. 인증키·쿼터·타임아웃·재시도·부분실패 격리, 실패 시 ERR-010, 미연계 항목 공백 처리(REQ-CO-004, A3). 배치 스케줄 + 수동 실행(API-114).

### 3.3 3D 자산 서빙(집구경)
평면도 상세(API-031)·자산 메타(API-032)로 2D/3D URL·포맷(glTF/GLB, Draco)·시점(1·3인칭, ITF-013) 반환. 관리자 업로드(API-122)는 용량/형식 검증(ERR-015)·(선택)트랜스코딩·서명 URL 발급.

### 3.4 개인정보·보안
청약 민감정보(무주택·소득·부양가족·연락처)는 **저장 암호화·컬럼 마스킹·최소 접근·접근 감사로그(API-192)**. 전 구간 HTTPS, 토큰 만료/재발급, 민감 액션 재인증(REQ-NF-005~007).

## 7. 일정·공수 요약
- 총 공수 약 **36 PW**. **크리티컬 패스:** A0 ERD → A2 공공연계(난이도 최상) → A4 자산 서빙 → A6 결제. 공공연계는 원천 API 편차로 버퍼 확보.
- 관리자 API를 각 스테이지에 포함해 **admin 저장소가 대기 없이 병렬 진행** 가능(문서간 Critical 해소).

## 10. 검증 & 검토 반영 이력
1. Phase 검토 phase-review-rule.md 준수·기록. 2. 타입/린트/단위·통합·부하 CI 강제. 3. API/인터페이스/오류가 대표 xlsx와 일치, 연관화면 유효(미존재 0건). 4. A1~A4 준수(실연동 시 목 제거, API 갭 문서 등록). 5. 비기능: 성능·보안·가용성(S7).

**검토 반영:** api-Critical(관리자 CRUD 완성·신청현황 API 추가)·문서간 Critical(관리자 API 소비 시점 재배치)·api-Major(공공데이터·개인정보 구체화)·api-Minor(3D 서빙·ERD)·C1~C5.
